# KidsProgress Design System (KPDS)

Source of truth: [packages/shared/src/design/tokens.ts](packages/shared/src/design/tokens.ts).
Generated artifacts: `apps/web/src/styles/tokens.css` + `tailwind.theme.json` (regenerated by `pnpm tokens:build`; NOT hand-edited).

## How it works

- One token shape, two themes (`parent`, `child`), selected at a single layout boundary via `data-theme`.
- Child portal has an additional `data-age="younger|older"` sub-theme.
- All UI reads tokens via Tailwind utility classes that compile to `var(--kp-…)` references. Never hardcode hex/px in components.
- The `ThemeBoundary` component is the ONLY place that sets `data-theme` / `data-age`. Hard rule.

## Hard "never" rules (enforced at code review)

1. **Never use raw hex / pixel values** in components — only Tailwind classes that map to KPDS tokens (e.g. `bg-bg`, `text-text-muted`, `min-h-touch`).
2. **Never animate or sound a kid failure.** The child portal does NOT use `red` or shake/bounce when a kid is wrong. Show neutral encouragement; let them try again calmly.
3. **Never show a numeric streak counter.** Only the opt-in "growing plant" glyph that does not regress on break.
4. **Never use mascots / gradients / celebrations on the parent portal.** Parent is calm + professional. Gradients (`bg-kp-sunrise` etc.) are reserved for `TaskTile` background + `TodayHero` ring on the child portal.
5. **Never set `data-theme` / `data-age` outside the `ThemeBoundary` component.** Theme switching happens at the layout boundary only.
6. **Never import `parentTokens` / `childTokens` directly into a component.** Components read CSS variables. Direct token imports only allowed in the generator (`scripts/build-tokens.ts`) and tests.
7. **Never bypass `prefers-reduced-motion`** — animations must respect the global rule in `globals.css`.
8. **Never compose Tailwind class names from variables** (`bg-kp-${name}`, `text-${color}` etc.). Tailwind's JIT only generates CSS for literal class strings it finds in source. Dynamic class names render as no-ops. Use a static map: `const STYLES = { sunrise: 'bg-kp-sunrise', ... }`.

## Approved surfaces for illustration assets

Restrict the 5 hand-drawn SVG illustrations to these surfaces only:

- Empty state
- "All done for today" celebration (child)
- Onboarding (parent)
- Auth / child-selection
- Child daily hero panel

All other surfaces use `@tabler/icons-react` icons.

## When adding a new component

1. Read this skill.
2. Look up the token group you need in `packages/shared/src/design/tokens.ts`.
3. Use the Tailwind class that maps to it (`bg-surface`, `text-text-muted`, `rounded-2xl`, `min-h-touch`, etc.).
4. If you need a value that isn't tokenized yet, add it to `tokens.ts` (both themes!) and re-run `pnpm tokens:build`. The contract test at `packages/shared/src/design/tokens.test.ts` enforces parity.
5. Test under both themes via the `/` demo page (or future shells).

## When reviewing a component

Flag any of:
- Raw `#`-prefixed colors or `px`-suffixed sizes in JSX className or inline style
- Direct token imports from a component
- Animations or color changes on failed child-side actions
- Streak counters as numbers
- Gradients used on the parent portal or outside Tile/Hero on child

Refer the author to this skill and the offending rule by number.
